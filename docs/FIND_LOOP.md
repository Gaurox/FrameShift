# Find Loop in Cut Video — 1.22.0

The private 29 October candidate includes improvement lots 0–9 and the automated lot 10 qualification. The canonical build from `f9c0444` passes **1,302 Release tests**, and the same-version installed application hash matches the new payload. Full interactive Windows acceptance remains open; see [the exact candidate, measurements and remaining gate](FIND_LOOP_VALIDATION.md#lot-10-candidate-qualification-on-29-october-2026).

Open **Cut Video** and click **Find Loop**. The first analysis uses Auto minimum and Normal sensitivity. Auto retains the one-second micro-loop guard on sources of at least two seconds; shorter sources use half their native video duration, aiming for at least three frames, capped by the available duration and a 0.1-second floor. A longer audio track does not set this video minimum. **Advanced options**, initially collapsed, contains the optional minimum duration, sensitivity, export repetitions and audio choice. An empty minimum means Auto; a numeric minimum is not a maximum source or candidate duration. **Stop search** cancels analysis and retains the current selection. Find Loop starts a new search after cancelling and cleaning up the preceding operation.

Candidates appear in a read-only native list showing start, exclusive end, duration and **Promising**, **Approximate** or **Needs review**. These are heuristic assessments, not percentages or guarantees; they use the same thresholds at every sensitivity. Best junctions come first, with duration and source time breaking equivalent scores. Static variants are grouped by duration family; different useful durations remain available. The three-result presentation limit is removed: the list shows the validated, deduplicated candidates retained by the search, with its budgets reported. Results arrive in batches; selection, custom bounds, duration sorting and scroll position are preserved. The list remains selectable while searching. Enter, Space and double-click in the list select without exporting. Editing bounds creates a **Custom selection** and keeps the original candidate intact; click its row or press Enter/Space in that row to restore it. Native times take priority; frame numbers are explicitly marked approximate until their ordinal mapping is indexed.

Boundary previews select the exact source image by its integer PTS. Start shows the first retained frame; End shows the last included image before the exclusive end, with that distinction stated next to the preview. The previous/next buttons move through real decoded VFR neighbors, retaining every queued click and the other boundary's native time. A time edit resolves the first included image; a frame-number edit resolves the actual decoded ordinal. These native choices are passed to both proxy rendering and loop export.

Native timing windows are cached independently of image pixels. No complete video index is required to select a candidate or step through its neighbors. The first request for an ordinal far into a source builds the required prefix on disk, with a visible indexing message and cancellation; subsequent nearby requests reuse it. The ordinal index is capped at **256 MiB**, using 24 bytes per frame, and time-window RAM is capped at eight windows of at most 4,096 timestamps. An interrupted extension retains the committed prefix, discards its partial chunk and allows retry. Closing removes the session index.

**Preview junction** renders a short, silent MP4 proxy containing the end then the beginning of the natural loop. The two windows are at most 1.5 seconds each, shortened for brief loops. There is one real seam inside the file, followed by playback stopping; the player does not seek or restart to simulate continuity. Native VFR intervals and the final image's hold are retained, including a sparse VFR tail held across the requested window. For longer forward/backward selections, two explicitly labelled separate clips show the end turn and start turn. Very short forward/backward selections use two continuous cycles so both direction changes are visible.

**Full loop preview**, under Advanced options, renders three continuous cycles with two internal cycle junctions. All previews use square-pixel proxies capped at **960 pixels** on the longest displayed side; scaling happens before the lossless intermediates and final encoding. Source rotation and pixel aspect ratio determine the proxy shape. Preview audio is always removed, regardless of Keep source audio or export repetitions. A full-resolution export still needs review for fine visual detail.

Playback uses FFmpeg pacing and a bounded bitmap buffer. **Stop preview** cancels rendering or playback. One preview bundle (one natural/full clip, or two distinct turning-point clips) is cached per session. Replay reuses it only when source path/size/modification time, selection, mode, speed, color/geometry/timeline metadata and render version match. Export audio and repetition changes do not alter the silent proxy. Changing a candidate/boundary/context cancels obsolete work and waits for the decoder before deleting cached files; closing also cleans the bundle. A render failure retains the selection and permits retry.

The shared timeline viewport reveals the loop tools and candidates. **Back to Cut** restores the Cut context and its **Export Selection** footer command while retaining the frame selection. Loop options are detached in Cut, and advanced fields are detached while collapsed. The footer stays outside scrolling content. Cancel and Escape close after cancellation and cleanup; they do not mean Stop search or Stop preview.

**Create forward/backward loop** is available without a natural candidate when the source color profile is supported. It plays the selection forwards then backwards, silently. Its speed control appears only in this context: 1x, 0.75x or 0.5x. For N decoded forward frames the cycle contains N + (N − 2) frames: the first and last frames are not duplicated at either turning point. At least three frames are required. VFR is explicitly resampled at the source average frame rate. Slow motion changes timestamps/output frame rate, keeping the frames rather than introducing duplicated endpoints.

The persistent primary footer command is **Export Selection** in Cut and **Export Loop** in either loop context, or **Export SDR Loop** when the color policy converts to BT.709. Enter outside the candidate list follows that command. Export is disabled during search, rendering, native timing resolution and context cleanup. Stop preview also cancels a pending native navigation/index request. Loop export uses the existing Cut Video queue and shared progress window. One repetition is the default; 1–10 are available in Advanced options. Natural mode retains source audio when present; forward/backward is silent. Output is adjacent, uniquely named `_loop.mp4` or `_pingpong.mp4` (with numeric collision suffixes). No Explorer menu was added. These source changes through lot 9 are not in the 24 October installer.

**Export All Candidates (N)** appears as a secondary footer command when Natural mode has validated candidates. It exports every displayed, deduplicated candidate in the current list order. Custom edits stay specific to the primary export; they do not replace the saved candidates. At the click, exact bounds, repeat/audio settings and source file identity are captured into an immutable batch. No extra confirmation is needed. The optional command is detached outside this context so ordinary Cut retains its original footer geometry.

The shared progress window processes candidates sequentially, with a distinct occurrence ID, candidate number, duration and exclusive bounds for each line. Display labels do not replace real source paths. **×** removes a waiting candidate or cancels only the processing occurrence; the others continue. **Cancel all** stops the current process and the remaining batch. A failed candidate keeps its error details while later candidates can succeed. Successful outputs remain saved; owned partial files are cleaned after process termination. Each request has its own read-only options and the existing adjacent collision suffixes. If the source changes after batch capture or between candidates, stale selections fail explicitly and completed outputs remain intact. The single-candidate CLI route is unchanged; batch analysis/export is an interactive command.

The open editor checks source path/size/modification/creation metadata before operations and periodically while shown. If the file changes or disappears, pending work is cancelled and candidates, still images, index and cached proxies are invalidated. Export is blocked with a request to reopen Cut Video, so old probe metadata is not silently reused for a replaced source.

## Rendering and audio

Loop output uses MP4/H.264 at CRF 18 and optional AAC 256 kbit/s. Video resolution, source pixel aspect ratio and displayed orientation are retained. Odd dimensions use H.264 4:4:4 instead of adding pixels; compatibility with some players is more limited. Natural loops preserve native frame timing, including VFR. Explicit concat durations retain the interval before the next cycle's first frame.

Find Loop announces **HDR source → SDR output** before searching. Confirmed PQ/HLG sources with BT.2020 primaries and a BT.2020 non-constant matrix are converted in software to SDR BT.709; bit depth alone never implies HDR. Analysis, native boundary images, junction/full proxies and exports share the same policy. PQ is linearized at a 100-nit SDR reference and Hable maps the maximum valid mastering/MaxCLL peak reported by the bounded probe (100–10,000 nits), falling back to 1000 nits when absent. HLG uses zimg's 1000-nit reference display. A missing range defaults to limited; explicit full range is honored. Missing or contradictory transfer/gamut metadata is diagnosed, without assuming PQ.

The software chain uses `zscale`, floating-point linear RGB, BT.709 primaries, `tonemap` and a dithered BT.709 limited-range conversion. The RGB frame is explicitly given BT.709 luma coefficients for highlight desaturation. HDR frame side data is removed and SDR tags are written into the output. Tagged BT.709 10/12-bit and SDR BT.2020 sources are converted without HDR tone mapping. The FFmpeg filter inventory is checked through the existing runner and cached by executable path/size/write time. An unavailable required filter disables conversion with an explicit diagnostic before source processing. Color conversion adds no frame-rate or timestamp operations. Preview cache identity includes range, peak and render version.

Other supported SDR profiles and untagged ordinary video retain their compatibility path; ambiguous high-bit-depth inputs remain blocked for loops. Ordinary Cut Video remains available. Other actions retain their historical color decisions. The bounded extra PQ metadata read examines at most 32 initial packets; dynamic HDR/Dolby Vision interpretation and preservation of HDR output are outside this lot. Synthetic ramp images were inspected; subjective acceptance on real HDR footage remains open. These source changes are not present in the 24 October installer.

Natural rendering uses presentation-ordered H.264 packets and sets the last packet's duration to the exclusive end boundary. This preserves the final frame's hold in a single exported cycle as well as inside the three-cycle preview, without adding a duplicate image. The duration correction uses FFmpeg's [setts bitstream filter](https://ffmpeg.org/ffmpeg-bitstream-filters.html#setts).

Native frame selection is resolved with FFmpeg timestamps instead of deriving VFR timing from average FPS. Natural export encodes one H.264 cycle into a temporary MOV, with presentation-ordered packets, a microsecond video clock and its exact final hold. Repetitions copy those encoded video packets rather than re-encoding the entire repeated duration. A requested start between images resolves to the first included native image before audio is trimmed. Source audio remains PCM in the temporary cycle, with initial offset/silence maintained and padding to its duration. All repetitions pass through one final AAC encode, avoiding an independently encoded AAC priming delay at each junction. Audio matching is **not analyzed**; retaining source audio does not imply a seamless audio loop. It can be muted in Natural mode. Previews and forward/backward processing retain their existing FFV1 intermediates.

Reverse processing uses small decoded chunks (estimated 128 MiB maximum, up to 120 frames each), followed by lossless concatenation. Natural, forward/backward and preview budgets account for their different artifacts; the natural temporary estimate stores one cycle regardless of repeat count. The 8 GiB temporary budget and available space are monitored during each process, with another output-space check based on the measured cycle before assembly. Natural decoding/filtering/encoding uses bounded thread and lookahead settings; this reduces peak memory but does not guarantee a speedup on every source. Final output can exceed the temporary budget when sufficient destination space exists. Preview budgets use proxy dimensions and actual excerpts, so a short junction is not rejected solely because the source is long or 4K. Long full-cycle previews can still exceed the budget and explicitly recommend Preview junction. Sparse VFR tails and neighbors are resolved in bounded blocks; pathological gaps can require several seeks. The first ordinal lookup can still be long because VFR frame numbers cannot safely be inferred from average FPS. A single exceptionally large decoded source frame can exceed the reverse chunk estimate. Normal cancellation/failure cleans owned workspaces only after confirmed process exit. If termination cannot be confirmed, export fails and logs retained paths instead of deleting files that may still be in use. Publication keeps the exclusive adjacent workspace and move without replacement; a late destination collision preserves the foreign file. Current-item cancellation keeps the original source identity during every phase, including reversal.

## Detection

The first pass samples at up to **8 FPS** in blocks of at most **256 RGB frames at 64×48**. Pixels are released after compact 8×6 color signatures are computed. A one-hour source retains 28,800 signatures at 8 FPS rather than reducing automatically to 1 FPS. The 57,600-sample budget covers up to two hours continuously at that rate; beyond it, distributed windows include both ends and explicitly report unsampled gaps.

Three spatial projections combine bounded appearance neighbors, time-spread visits to equal signatures and duration-family targets. Up to **24 temporal regions**, duration families and two retained alternatives per region/family share a budget of **192 refinement tracks**, replacing the old global 16-track shortlist. Bucket/track pruning is reported, and native frames are never compared all-pairs across the whole source. Sensitivity affects both preselection and native validation. The actual source end is resolved from video timing, including a bounded clock-tick reconciliation for video-only container duration rounding.

The second pass decodes windows at native frame timing, up to 384 frames per window, for sources up to 240 FPS. Unlike the coarse pass, it retains the displayed aspect ratio, rotation and pixel aspect ratio, capped at 192 pixels on the longest side. Signed velocity and the actual end→start movement contribute before the best 24 pairs are verified spatially. Up to three distinct local variants are retained from a track. Context adapts to motion between 120 and 350 ms, using at most five time-aligned image comparisons instead of a fixed count of neighboring frames. Appearance, local lighting, time-normalized movement, seam continuity and scene changes remain separate metrics. The whole-source seam and file boundaries use available native context; chaotic acceleration without exterior evidence cannot cancel all seam error and produce a perfect assessment. The worst 8×8 spatial tile contributes strongly so a static background does not conceal small changing details. Opposite movement, a skipped phase, an artificial pause, lighting differences and scene discontinuities increase error or reject the junction. Static sequences remain valid; no division by motion magnitude is required.

Quality is a **heuristic estimate**, not probability or a guarantee. The search is bounded and does not prove that no loop exists. Sparse sampling in long videos can miss short cycles, fast/small foreground motion can disappear at reduced resolution, and chaotic footage may produce approximate junctions. Always preview. Inspiration: [Andyland's FFmpeg difference example](https://andyland.info/wordpress/use-ffmpeg-to-find-a-possible-loop-in-a-video/); FrameShift searches multiple starting points, avoids an all-keyframe preliminary transcode and checks temporal continuity.

Analysis records sampled/native decoded frames, timing-only endpoint reads, block count, compact signature payload, compared pairs, regions, examined tracks, accepted candidates, phase timings, refinement dimensions/resident frames and the largest RGB temporary file. Candidate metrics are retained with the immutable results; diagnostic logs include the leading candidates. Snapshots distinguish in-progress batches from a completed bounded search. Up to **512 deduplicated results** are retained; pruning at that guard is explicit. Flags separately identify sampling, bucket/track budgets, result budgets and unsampled temporal gaps. Cancellation still throws `OperationCanceledException`; completed search never certifies exhaustiveness. The [validation report](FIND_LOOP_VALIDATION.md) contains one-hour measurements, decoded quality comparisons and the limits of the initial perceptual calibration.

## CLI

Detection remains interactive in Cut Video. CLI export uses explicit existing cut boundaries plus:

```text
FrameShift.exe --action cut-video --start-frame 7 --end-frame 36 --loop-mode natural --loop-repeat 3 --loop-audio keep "C:\Media\vidéo été.mp4"
FrameShift.exe --action cut-video --start-frame 7 --end-frame 36 --loop-mode pingpong --loop-speed 0.5 --loop-repeat 3 --loop-audio mute "C:\Media\vidéo été.mp4"
```

`--loop-mode natural|pingpong`, `--loop-speed 1|0.75|0.5`, `--loop-repeat 1..10`, `--loop-audio keep|mute`. Natural speed is 1; Ping-Pong requires mute. These are export options, not a headless Find Loop analysis API. Without loop options, existing cut behavior is preserved. UI candidate timestamps are transported internally; they are not public CLI switches.

## Qualification

Automated coverage: cyclic animation, rotating object, evolving lighting, opposite motion, changing foreground over a static background, random chaotic frames, static video, short/corrupt/audio-only inputs, MP4/MKV/MOV/WebM sources, portrait/orientation, audio presence, VFR intervals, three Ping-Pong speeds, endpoint order, multi-chunk reversal, unique publication, cancellation, accented paths, WinForms layout and decoder lifetime. Local private footage is exercised when present; it is not a dependency of the portable suite. Tests also inspect decoded exports across both repeated transitions, not only similarity scores.

Recorded test results and remaining manual acceptance belong in [FIND_LOOP_VALIDATION](FIND_LOOP_VALIDATION.md). The code uses existing runners exclusively; the project and package lockfiles gain no dependency. Inno Setup obtains version 1.22.0 from the canonical script and packages the app assembly and FFmpeg tools. Run `build_installer.ps1` from the intended clean commit; `-AllowDirty` is only for an intentional local dirty build. Installation and publication are distinct acceptance steps. The 29 October candidate was rebuilt from a clean commit and reinstalled; it is not publicly released or fully manually accepted.
